# Qryx 1.0.0

The crypto plane of the TAIPANBOX stack: an inventory of the cryptography in
code, binaries, container images, live TLS, certificates, dependencies and
cloud KMS, scored for post-quantum readiness, written out as a CycloneDX 1.6
CBOM and as signed evidence a third party can verify. It inventories an
organisation's own cryptography; it acts on nothing beyond a diffed key-size
fix.

## What 1.0 promises

`compat/1.0.json`, rendered as `COMPATIBILITY.md` and held by
`scripts/compat-surface.sh` on every push: the twelve subcommands, the four
agent-event types this plane emits (`crypto_finding`, `crypto_drift`,
`policy_violation`, `evidence_signed`), the three schema strings it accepts on
read, CycloneDX 1.6 for the CBOM, and the ten fields of an evidence-trail
record. A frozen name is not removed or renamed within this major; a new
detector is a new finding, never a removed one; a new output format, flag or
connector subcommand is additive. Support line: the newest minor gets every
fix; the previous minor gets security-relevant fixes for 90 days after the
newer one is tagged.

## Since 0.3.1

- The CBOM says only what CycloneDX 1.6 lets it say: every enum value is
  mapped at the boundary, never copied from the internal vocabulary (#53,
  invariant 18). Found by the 1.0 proving run, below.
- The numbers that flattered a scan were corrected, one theme in six
  findings: an algorithm this tool never graded is `not-assessed` and in the
  denominator, not `compliant`; CNSA remediation follows the finding, not
  only its risk class; a manifest naming a crypto library is not an RSA
  asset; a comment about RSA is not a use of RSA; an AES key whose size was
  never read is not AES-256; a source with no agility row is named, not
  scored low in silence.
- Nothing reads as clean that could not look: `gcp` inventories every
  location and reports partial coverage; a failed image extraction is never
  a clean image; the walk counts what it could not examine; a missing
  baseline is not a gate that passed (`--allow-missing-baseline` says when a
  first run is genuinely the first).
- The agent-event chain is verified cryptographically (RFC 8785 canonical
  hashes through `agent-stack-go`), a chain head is legal, and the two chain
  verdicts get their own CNSA remediation (#41, #42, invariant 16).
- `--format ai-inventory`: an AI code inventory another program can read,
  with Azure OpenAI, Vertex AI and the registered Bedrock id (#29, #31, #33).
- `components.json`: qryx reads no environment, and its exit codes mean the

- `agent-stack-go` v1.0.0, the contract at 1.0 (#48); Go 1.27 GA (#26).
- Every release is signed, attested and carries SBOMs (#49); workflows run

## Upgrade note, 0.3.x to 1.0.0

- **The compliance percentage moved, on purpose.** A scan of 0.3.1 scored
  every unrecognised algorithm `compliant`; 1.0.0 scores it `not-assessed`
  and keeps it in the denominator. The same tree can score lower under 1.0.0
  with nothing in it changed, and `trend --fail-on-regression` across the
  boundary can fire on the definition, not on the code: read the first 1.0.0
  evidence record as a new baseline.
- Evidence trail on Postgres: the `not_assessed` column is added by
  `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` the first time 1.0.0 connects; a
  record written before it decodes with `notAssessed: 0`, which is what it
  meant at the time. A JSONL trail needs nothing.
- CBOM consumers: a `cryptoProperties` value is now the spec's enum. A reader
  that matched the internal strings (`encryption`, `key-exchange`, a `library`
  crypto asset) sees the mapped values instead; a library is a `library`
  component with no `cryptoProperties`.
- The bus: 1.0.0 emits the same four types under the same schema version
  (v0.1) and accepts what 0.3.x accepted. Exit codes are unchanged: 0 ran, 1
  tool or usage error, 2 a gated finding, 3 a policy violation or a trend
  regression.
- Release asset names carry no version, as before; `qryx version` carries it.

## Not in this release, said plainly

- The CBOM is held inside the 1.6 vocabulary by a test over the enums copied
  from the schema, not by validation against the live schema file.
- `qryx fix --open-pr` shells to `git` and `gh` behind an interface seam; the
  orchestration is table-tested, the real git path is not.
- The AWS, GCP and Azure connectors are proven against their pure mappers
  and the interface seam; no live account ran in the proving run.
- A stripped, statically linked binary is invisible to `qryx bin`: a clean
  binary scan is not proof of absence (invariant 6).
- The dashboard and the HTML report pages are experimental in
  `compat/1.0.json` and may change in a minor.
