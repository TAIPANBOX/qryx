# Qryx 1.0.1

A patch release on the 1.0 surface. The change a person is most likely to notice is a fix to what `qryx agents` and `verify-evidence` claim. Nothing frozen in `compat/1.0.json` moves, and no exit code changes outside CI mode.

The `qryx` image, `ghcr.io/taipanbox/qryx`, is signed in the legacy `.sig` format that the cluster admission controller (policy-controller v0.15.1) reads, so the signature is verifiable there. Its reader takes only that tag, and before this release the image signature was not. cosign stays at v3.1.3, and the release workflow's `sign-blob` steps are unchanged.

## Fixed

- **A passport's attestation method is reported as declared (#73).** An Agent Passport names its attestation method in its own JSON. qryx reads no certificate, SVID or enclave key behind that name, but its findings said "attests via mtls-cert" as if the mechanism had been checked. Every finding text for a passport's method now says the method is declared, and it is marked not verified where a mechanism is named.
- **`verify-evidence` does not pass a document re-signed by an unpinned key (#73).** With no signer pinned, a rewritten and re-signed document used to pass. Outside CI mode an unpinned check is now reported as "not verified: no signer pinned", never as VERIFIED. The new `--ci` flag makes an unpinned check a refusal, so a CI step cannot pass on a forgery. Exit status outside CI mode is unchanged.

## Changed since v1.0.0

Twenty-two commits lie between the 1.0.0 tag and this release. Besides the fix above:

- **The agent-stack-go pin moves to the v2 module path, v2.0.0 (#74).** The shared wire-type import moves to `github.com/TAIPANBOX/agent-stack-go/v2`. Nothing an operator sets or sees moves with it.
- **The agent-stack-go pin moves through v1.0.1, v1.0.2, v1.1.0, v1.2.0 and v1.3.0 (#57, #58, #61, #70, #71).** Dependency bumps, before the v2 move.
- **The Go toolchain is go1.27.2 (#63), and the estate secret scan runs on every pull request (#64).** Build and CI changes.
- **The manifest test checks every environment read against `components.json` (#67).** A test and a manifest check, no runtime change.
- **Documentation (#62, #66, #68, #69).** The README's version and toolchain statements, the dated figures and the environment invariant's scope.
- **The image is signed in the legacy format (#75).** The image sign step adds `--new-bundle-format=false --use-signing-config=false`, with a comment above it. Remove both flags when policy-controller reads bundles.
- **Actions bumps (#59, #60, #65 and one in dc8f34b).** Each still pinned to a commit.

## Upgrade

Nothing to change in a deployment. Pull `ghcr.io/taipanbox/qryx:v1.0.1` in place of `v1.0.0`. A CI step that verifies evidence should add `--ci` and pass a pinned signer, since an unpinned check is now a refusal in that mode.
