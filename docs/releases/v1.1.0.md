# Qryx 1.1.0

This is a minor release, not a patch, because the move to agent-stack-go v2 (below) changes how event stream files are created.

## Upgrade first: the event stream file

Since agent-stack-go v2, a stream file this service creates is mode `0640`, not `0644`: the owning account and its group can read it, and no other account can. A new stream file is created only in a directory this service's account owns. An existing file is opened as it is.

A bus directory that is shared between services and not owned by qryx's account gets no new stream, unless each file is created beforehand by the uid of the service that writes it. Before you start 1.1.0, check who owns the bus directory and the mode of each stream file in it. stack-single creates its files this way; a deployment that does not must do the same.

## Upgrade: the evidence check

A CI step that verifies evidence should add `--ci` and pass a pinned signer. Outside CI mode an unpinned check is reported as "not verified: no signer pinned", never as VERIFIED, and with `--ci` it is a refusal, so a CI step cannot pass on a forgery.

Pull `ghcr.io/taipanbox/qryx:v1.1.0` in place of `v1.0.0`.

## Fixed

- **A passport's attestation method is reported as declared (#73).** An Agent Passport names its attestation method in its own JSON. qryx reads no certificate, SVID or enclave key behind that name, but its findings said "attests via mtls-cert" as if the mechanism had been checked. Every finding text for a passport's method now says the method is declared, and it is marked not verified where a mechanism is named.
- **`verify-evidence` does not pass a document re-signed by an unpinned key (#73).** With no signer pinned, a rewritten and re-signed document used to pass. Outside CI mode an unpinned check is now reported as "not verified: no signer pinned", never as VERIFIED. The new `--ci` flag makes an unpinned check a refusal, so a CI step cannot pass on a forgery. Exit status outside CI mode is unchanged.

## Changed since v1.0.0

Twenty-two commits lie between the 1.0.0 tag and this release. Besides the fix above:

- **The agent-stack-go pin moves to the v2 module path, v2.0.0 (#74).** The shared wire-type import moves to `github.com/TAIPANBOX/agent-stack-go/v2`. This is the change described under Upgrade first.
- **The agent-stack-go pin moves through v1.0.1, v1.0.2, v1.1.0, v1.2.0 and v1.3.0 (#57, #58, #61, #70, #71).** Dependency bumps, before the v2 move.
- **The Go toolchain is go1.27.2 (#63), and the estate secret scan runs on every pull request (#64).** Build and CI changes.
- **The manifest test checks every environment read against `components.json` (#67).** A test and a manifest check, no runtime change.
- **Documentation (#62, #66, #68, #69).** The README's version and toolchain statements, the dated figures and the environment invariant's scope.
- **The image is signed in the legacy format (#75).** The image sign step adds `--new-bundle-format=false --use-signing-config=false`, with a comment above it, because the cluster admission controller (policy-controller v0.15.1) reads only the legacy `.sig` tag. cosign stays at v3.1.3. Remove both flags when policy-controller reads bundles.
- **Actions bumps (#59, #60, #65 and one in dc8f34b).** Each still pinned to a commit.
